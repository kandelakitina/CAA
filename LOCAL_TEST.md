# Локальное тестовое окружение Windows

Требуются PowerShell 7 и Go. Docker, WSL и системные службы не используются.
Переносимые серверы, журналы, случайные пароли и данные находятся в `.local-test/`;
папка исключена из Git. Скрипты не читают `.env` приложения и не подключаются к Timeweb.

```powershell
# Только при первоначальной установке на другом компьютере:
./scripts/install-local-test.ps1

# Запуск серверов и интеграционного теста:
./scripts/local-test.ps1 -Action Test

# Только запуск серверов:
./scripts/local-test.ps1 -Action Start

# Остановка с сохранением данных:
./scripts/local-test.ps1 -Action Stop
```

В песочнице Codex инициализация PostgreSQL и доступ к локальным сокетам могут
потребовать разрешения на выполнение команды вне песочницы Windows.

PostgreSQL 17.6 слушает `127.0.0.1:55432`, база и пользователь — `neva_local_test`.
SeaweedFS 4.46 предоставляет S3 API на `http://127.0.0.1:18333`, тестовый бакет —
`neva-local-test`. Вспомогательные HTTP-порты: 18080, 18888, 19333; gRPC — на
соответствующих портах +10000. Все привязаны к loopback. Телеметрия SeaweedFS отключена.
Не публикуйте эти порты в интернет.

Пароли генерируются при первом запуске и сохраняются в `.local-test/settings.json`.
Скрипт не печатает их. PostgreSQL использует SCRAM, S3 требует подписи запросов.
Управление SeaweedFS через вспомогательные локальные порты предназначено только
для этого тестового окружения. Это окружение не подходит для размещения рабочих данных.

Тест запускается с флагом сборки `localintegration` и отдельным разрешающим
переключателем окружения. Дополнительно проверяются точные локальные адреса и имена
базы/бакета. Каждый прогон создаёт новую схему PostgreSQL. В конце он проверяет
архивирование и полный сброс только этой схемы, включая удаление её файлов из S3.
Данные предыдущих прогонов не очищаются. Обычный `go test ./...` не обращается
к этим серверам. Лимит локального SeaweedFS увеличен до 32 томов по 64 МБ.

HTTP-проверка использует настоящий маршрутизатор приложения, TLS-сервер на случайном
локальном порту, cookies, вход и CSRF. Сервер HTTP существует только во время теста;
после завершения теста постоянного интерфейса приложения в браузере нет.

Источники архивов: [PostgreSQL от EDB](https://www.enterprisedb.com/download-postgresql-binaries)
и [SeaweedFS 4.46](https://github.com/seaweedfs/seaweedfs/releases/tag/4.46).
Версии и SHA256 зафиксированы в установочном скрипте. SHA256 SeaweedFS опубликован
GitHub; SHA256 PostgreSQL зафиксирован после загрузки по HTTPS с сервера EDB.

Локальный SeaweedFS проверяет совместимость S3 API, но не настройки Timeweb:
сетевую доступность, ограничения прокси и поведение конкретного бакета нужно
проверять отдельно после согласованного развёртывания.

Проверено 8 сентября 2026: установка из сохранённых архивов, запуск, сквозной тест,
остановка и повторный запуск с сохранением данных. Пройдены также обычные Go-тесты,
`go vet`, сборка и проверка diff. Серверы после подготовки оставлены запущенными.
