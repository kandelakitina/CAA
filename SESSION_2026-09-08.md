## Question cancellation

The owner approved proceeding with question cancellation as the next bounded
development step.

- Secretary-only POST `/questions/:id/cancel`, protected by session and CSRF.
- Mandatory trimmed reason of 1–2000 characters.
- Draft, internal review, revision required, ready for Committee, Committee
  voting, rejected and no-quorum questions can be cancelled.
- Approved and already cancelled questions cannot be cancelled.
- The transaction locks the question, cancels active internal/Committee rounds,
  writes round audit events, records the reason/time/secretary name and writes
  `question.cancelled`. An audit error prevents commit.
- Files, versions, visas and votes remain intact. Pending file versions retain
  their history but can no longer be confirmed/rejected on a cancelled question.
- The card displays cancellation details and hides further mutation controls.
- Committee readers retain access to cancelled questions and downloads only
  when a Committee round exists; cancelled pre-Committee drafts remain hidden.
- Three additive, repeatable column migrations; no new configuration or
  production dependencies.

## Continuation: post-review decision text revisions

The owner requested continuation. The worktree was clean at the start.
Implemented a secretary-only revision form with required new text, reason,
deadline and explicit visa policy. The workflow requires previous internal-review
history and no active internal/Committee round. Drafts returned from cancelled
rounds, revision-required, ready-for-Committee, rejected and no-quorum questions
are eligible; approved/cancelled questions are blocked.

`recheck_all` requests all visas again. `carry_positive` copies only positive
visas for unchanged file versions from the latest internal round, retaining the
original visa ID, decision author/time and attachment references. Missing visas
and changed files get new assignments. Rejected files require a new official
version under either policy. Pending uploads and incomplete mandatory bundles
block the operation. All four services must have active representatives.

One transaction locks the question, checks the stale-form token, creates the
internal round/requirements/carried visas, writes an immutable text revision,
updates the question and writes audit. All-carried rounds finish automatically;
others await their new visas. Active Committee voting must first be cancelled.
Old Committee-start forms now fail if the question timestamp has changed.

Added `decision_text_revisions` with an update/delete prevention trigger and
nullable `internal_review_rounds.frozen_decision_text`. Initial and file-revision
rounds also save text snapshots. Historical NULL snapshots stay NULL and are
clearly labelled, rather than inferred from current text. The question card shows
revision history and source text/round information for carried visas.

Tests cover validation, role/CSRF gates, input escaping, allowed states, stale
