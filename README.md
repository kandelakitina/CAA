# Neva Approvals

Закрытое веб-приложение для размещения, версионирования и согласования
корпоративных документов. Приложение развёртывается как самостоятельный сервис
в Timeweb Cloud App Platform.

Описание предметной области, ролей, согласований, голосований Комитета,
протоколов и связанных организационных правил вынесено в
[BUSINESS_LOGIC.md](BUSINESS_LOGIC.md).

## Технологический стек

- Go и веб-фреймворк Gin;
- серверный рендеринг HTML-шаблонов и лёгкие HTMX-style взаимодействия без SPA;
- PostgreSQL через `pgx`;
- приватное S3-совместимое объектное хранилище;
- сессии и ролевая авторизация на стороне сервера.

Метаданные, пользователи, сессии и история операций хранятся в PostgreSQL.
Загруженные файлы хранятся в приватном S3-бакете и выдаются только после
серверной проверки прав доступа.

Миграции базы данных выполняются приложением при запуске. Они рассчитаны на
повторный запуск и существующую базу данных.

## Требования

- актуальная версия Go, указанная в `go.mod`;
- PostgreSQL;
- S3-совместимое объектное хранилище.

Для изолированной проверки на Windows без Docker подготовлены переносимые
PostgreSQL и S3-сервер, команды запуска и остановки, а также сквозной HTTP-тест:
[LOCAL_TEST.md](LOCAL_TEST.md). Обычный `go test ./...` не требует этих серверов.

## Локальный запуск

```bash
go mod download
go run .
```

По умолчанию приложение доступно по адресу `http://localhost:8080`. Проверка
состояния сервиса: `GET /health`.

HTTP-сервер использует переменную `PORT` и слушает все сетевые интерфейсы;
если переменная не задана, используется порт `8080`.

## Конфигурация

Конфигурация передаётся через переменные окружения. Реальные пароли, ключи и
другие секреты нельзя сохранять в репозитории.

### PostgreSQL и приложение

- `PORT` — порт HTTP-сервера, по умолчанию `8080`;
- `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`, `PGSSLMODE` —
  подключение к PostgreSQL;
- `SESSION_SECRET` — секрет для защиты пользовательских сессий;
- `INITIAL_ADMIN_EMAIL`, `INITIAL_ADMIN_PASSWORD` — данные первого
  администратора для пустой базы;
- `INITIAL_ADMIN_NAME` — имя первого администратора, необязательная переменная.

После первого успешного входа `INITIAL_ADMIN_PASSWORD` следует удалить из
переменных App Platform: в PostgreSQL уже хранится хэш пароля.

### Объектное хранилище

- `S3_ENDPOINT` — адрес S3 API;
- `S3_REGION` — регион;
- `S3_BUCKET` — имя приватного бакета;
- `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` — ключи доступа.

Проверка соединения с хранилищем доступна администратору. Маршрут
`/admin/storage/check` также защищён серверной проверкой роли.

### Электронная почта

Настройка SMTP для приглашений, восстановления доступа и уведомлений описана в
[SMTP.md](SMTP.md).

## Развёртывание в Timeweb Cloud

- тип приложения: `Backend → Gin`;
- команда сборки: `go build -o app .`;
- команда запуска: `./app`;
- health-check: `/health`;
- директория проекта: пустая, если репозиторий размещён в корне приложения.

Приложение, PostgreSQL и S3 настраиваются переменными окружения. Развёртывание
само по себе не удаляет данные. Новые производственные зависимости для текущей
схемы не требуются.
